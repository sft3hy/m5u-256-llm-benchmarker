Engine Architecture: MLX vs llama.cpp

Testing identical model checkpoints across multiple frameworks uncovers significant runtime overhead variances:

  • mlx-lm (Apple MLX): Native Swift/C++ Metal integration tailored specifically for Apple Silicon registers and unified memory caching.
  • oMLX: Server architecture incorporating continuous batching and tiered KV cache paging.
  • llama.cpp: Highly portable C++ with Metal kernel acceleration, utilizing the community GGUF container standard.

Executive Takeaways for Local Inference

  1. Dense 27B-31B is the sweet spot: Models like Qwen 3.8-27B and Gemma 4-31B deliver comfortable conversational speed while leaving abundant headroom for massive context windows.
  2. MoE architectures reward unified memory: High total parameter counts with low active parameter footprints (e.g. Qwen 3.8-Flash-Next) achieve remarkable decode velocity when memory bandwidth is sufficient.
  3. Framework optimization is free throughput: Choosing MLX-native runtimes often yields 15–30% throughput gains over generic cross-platform ports.
